## 可重复检查

```bash
mvn -B verify
python3 -m unittest discover -s judge-tests/tests -v
python3 -m unittest discover -s tools/tests -v
cd oj-web && npm ci && npm run build
```

独立环境中还执行五语言正常判题、WS 定向收包、镜像 `build.sh --verify-only`、管理端 16 项检查与排行榜/历史删除真实接口回归。管理检查命令见 judge-tests/README.md；仅使用独立管理员 token，测试栈不能连接业务库。演示数据不能替代真实评测证据。

## 部署前

- 新库导入当前 schema；旧库按实际字段/索引状态升级，停止旧评测实例后再启新版本，不能重复 ADD COLUMN。
- 复制 deploy/.env.example 为 deploy/.env，填写实际部署凭据和新的 JWT 密钥。真实 .env 已排除出 Git 和构建上下文。
- 在 Linux/WSL Docker 环境构建并自检五镜像，保持宿主与 judge 的工作目录绝对路径一致。
- 启动服务后，用真实账号完成一次提交，核对终态、用例明细和资源统计；确认课程、竞赛、排行榜与监控页面可见。
- CI 工作流随本次代码提交后运行；如果团队需要强制通过才能合并，需要在 GitHub 配置相应必需检查，不能只依赖可跳过的本地 hook。
